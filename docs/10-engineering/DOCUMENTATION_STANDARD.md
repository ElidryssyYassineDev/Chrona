# Documentation Standard

**Document ID:** ENG-010

## Purpose

Documentation is part of the product.

## Principles

- Documentation precedes implementation.
- Documentation evolves with the system.
- Every architectural decision has a home.

## Documentation Categories

- Vision
- Product
- Domain
- Architecture
- Engineering
- ADRs

## Requirements

Update documentation whenever:

- Architecture changes
- Business rules change
- Public APIs change
- Domain terminology changes

## Quality

Documentation should be:

- Accurate
- Concise
- Versioned
- Reviewable
- Cross-referenced

## Final Rule

Outdated documentation is a defect.
